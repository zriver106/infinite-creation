## B 提示词格式与标签

# H3 Prompt Writing

### 〔B-001〕 Project rule: no in-shot score — `non_diegetic_music: N/A`

Every shot's video prompt in this project writes the music section as exactly `non_diegetic_music: N/A`, in the base modes and in Ref2VA alike. No music is generated inside a shot.

- Why: all scoring is laid in post when the chapter is assembled, from the chapter BGM and its cue table (`set_chapter_music` / `set_chapter_music_cues`). Music generated inside a shot clashes with the chapter BGM and breaks the main track's resume-from-breakpoint after a silent or inserted segment.
- This overrides the music examples in `references/base-en.txt` §4.7 and `references/ref-en.txt` §6; they remain a format reference only.
- Do not describe background music, score, BGM or a soundtrack anywhere else in the prompt either (not in `overall_soundscape`, not in the body). Sound the characters can hear in the scene (a radio, a ringtone, a street musician) is ambience: write it in `overall_soundscape` only when the story needs it.
- Free-text prompts (the `Sound: … Background music: …` style) write no music sentence at all; if a music slot must be filled, write `Background music: none.` The `Sound:` sentence carries only sound heard in the scene. When rewriting an existing prompt that has a `Background music:` sentence, delete it.
- Do not bind `music` assets as a shot's audio reference (`audios`); only voice and sfx assets go there.
- The render-time music check (`lib/core/music-check.js`) warns when `non_diegetic_music` is not N/A, when an H3-sectioned prompt has no `non_diegetic_music` section, or when a shot binds a `music` asset.

### 〔B-002〕 Output Rules

- Write rewrite sections in English; preserve dialogue, lyrics, and visible scene text in their original language.
- Describe each shot by composition, subjects, environment, actions, camera, sound, and the exact point where referenced content appears.
- **Character appearance: write only the clothing ID, never a look description (R22, rewritten 2026-11-23 rulepack-lock-20261123; 总导 2026-11-23 03:36 批准)**: a character's image reference carries the face, age, hair texture, skin, build, fabric, materials, shoes, accessories and trims, so the prompt never describes them. (1) **Reference line = who, not what they look like:** write character name + role/identity, e.g. `__MINIMAX_H3_REF_1__ is Ye Xueji's spirit body`; never add age, facial features, face shape, skin, build, materials, shoes, accessories or trims. (2) **When to write the clothing ID:** write one short clothing ID — colour + main garment + hair, e.g. `grey-blue short-sleeved T-shirt, dark grey trousers, short black hair` — for each bound character (a) in every shot with two or more people on screen, (b) in every shot, solo shots included, of a scene where any shot has two or more people on screen, and (c) whenever the story puts the character in a state the bound image does not show (injury, dirt, wet, exhaustion): add that state as words after the clothing ID, at the degree the novel gives, e.g. `a small scrape on the right cheekbone`. A solo shot in a scene that only ever has one person writes no clothing ID. (3) **Where the words come from:** copy the clothing ID from the bound costume asset (or the character asset when no costume is bound) and from the costume-state trajectory table when one exists; keep it word-for-word identical in every shot of the scene until the story changes the costume (see *Same-scene presence and costume lock* items 2, 4 and 11). Write it in the reference line or the headcount lock sentence, never as a separate appearance paragraph. (4) **Never** write `keep the look of __MINIMAX_H3_REF_N__`, `keep the look of each reference`, `stay faithful to the reference image` or any similar sentence (these make the shot drift into the reference image at its end); end the prompt with the live-scene lock instead, e.g. `The last frame is still the live <scene> scene.` (5) If the task input supplies a character's look (asset description, character bible, continuity notes, 「角色一致性」 line), take only the clothing ID out of it under (2)–(3); do not copy anything else. This rule overrides the `keeps the look of <Picture N>` advice in references/ref-en.txt. Scenes, props and environments are not covered by this rule — describe them normally.
- **Make every character action emotion-driven and physically specific**: never write only inert/still verbs (stands / sits / walks / looks) with no force. State the action's intensity, speed, and body language so the motion has visible energy (e.g. `slams the table`, `paces frantically`, `clenches his fists`, `leans in intensely`, `snatches the letter`, `stumbles back breathless`) — and keep the action consistent with that line's emotion. Static characters plus a monotonous read come across as lazy; give each beat visible, purposeful movement. **Inner-monologue exception:** in an OS block the force goes into the eyes, brows, head, hands and body only — never into the mouth (see “Inner-Monologue (OS / 心声) Shots”).
- Avoid plot summaries, unresolved reference labels, and timing that does not match the requested duration.
- **Speaker IDs follow the speaking order inside this shot**: each IC shot is its own video, and H3 gives `(S1)` to the first voice heard in it and `(S2)` to the next new voice (`references/ref-en.txt` §5.4). So the first voice in this shot, OS included, is `(S1)`; never fix an ID for the whole chapter. The voice-reference line uses the same ID as that character's lines, whatever its REF number (`__MINIMAX_H3_REF_4__ is Jiang Che's voice (S2)` is fine); in the OS fixed sentences `(S1)` means the OS speaker's ID in this shot. Jobs 70f12d2f shot 17 and 231e6bc2 shots 1–2 tagged the shop owner, who spoke first, `(S2)`: both voices came out swapped.

### 〔B-003〕 No style-lock sentence; live-action lock instead — 不写画风锁定句，改写实景锁

H3 reads any sentence that ties the shot's look to a reference image as "show the reference image". The end of the shot, or the whole shot, then turns into the reference picture, a character sheet or a grey backdrop, and the reference's rendering style is locked in.

1. **Applies to:** every shot and every field that reaches H3 (`subject_definitions`, `summary`, `detailed_description`, `retention_analysis`, sub_shots).
2. **Never write:** `keep the look of __MINIMAX_H3_REF_n__`, `keeps the rendering style of the reference images`, `stay faithful to the reference image`, `same as (the) reference`, or any paraphrase that asks the shot to look like a reference. Identity already comes from the definition line (`__MINIMAX_H3_REF_k__ is <name>: <clothing ID>`); no extra "keep the look" wording is needed.
3. **Write instead (when the bound image is a sheet, a multi-view board or has a grey background, or the shot ends on a still beat):** at the start `From the first frame to the last frame this is the live-action <location>; it never turns into a reference image, a blank background or a grey studio backdrop.` and at the end `The last frame is still the same live-action <location>.`
4. **Wrong:** `... she turns back to the window, keeping the look of __MINIMAX_H3_REF_1__.` **Right:** `... she turns back to the window. The last frame is still the same live-action seafood buffet restaurant.`
5. **Check:** h3_prompt_lint ERROR `STYLE_REF_KEEP` (r66, extended r85) already blocks these phrases before rendering. When you rewrite a shot, delete the sentence from that shot. Do not widen a fix to other shots only for this sentence; how existing hits in untouched shots are cleared is decided by 总导.

### 〔B-004〕 Visual follows the prompt — 改提示词就同步重写 visual

`video_prompt` is what renders. Whenever you write or change a shot's `video_prompt`, rewrite these parts of that shot's `visual` from the new prompt in the same PATCH, then read the two back together:
- who is in frame, who enters or exits, and who is only a voice;
- whether each person stands, sits or walks, and where each one is;
- movement direction and camera direction;
- what each hand holds and where the props sit;
- what any system UI or screen shows;
- the end-frame state.

When `visual` and the prompt disagree, the prompt wins and `visual` is rewritten to match.
- **Never edit only `visual` to get past a lint check if that makes it contradict the prompt.** Example: writing "the panel has not appeared yet" when the prompt opens the panel at 1 s. Fix the prompt or the binding instead, or report the lint item and ask for a waiver.
- Before handing a batch in, compare each changed shot's `visual` with its prompt on the items above. List every contradiction in the report.

#### 〔B-005〕 B-005【待测】IC 提示词的时间段只用整秒（TR-V13）

`N-Ms:` 时间段、`runs from` 句里的秒数一律写整数；不写 0.5s 这类小数。

#### 〔B-006〕 B-008【待定】画风基线

唯一风格句由总导定稿后写入本条；定稿前不改各镜现有风格句，也不写任何把画面锁到参考图的句子（见本类「不写画风锁定句」）。

## C 心声

### 〔C-001〕 Inner-Monologue (OS / 心声) Shots — hard rule (r19 rewrite 2026-11-24, Andy 18:34–18:48; template = the Han Zhicheng inner-voice shot Andy approved)

An inner-monologue line is a character's silent thought heard as voice-over. The character on screen must **never** move their lips for it. H3 lip-syncs any `<d>` line to whoever looks like the speaker unless the prompt makes the closed mouth explicit, so follow these rules exactly whenever a shot contains an inner-monologue line.
**Void (r19):** the 17:25 version of rule 8 (`<Name> (S1) … says in an off-screen voiceover`): name + `says` binds the voice to the visible person. The template is the V2 6#3 (1D5C7A14) sentence `An off-screen male inner-monologue voice (S1), <emotion>, <pace>, <timbre> narrates <d>…</d>.` (rule 8).

**1. How to recognise an OS line.** A dialogue/sub-shot line is inner monologue when the speaker label carries `（OS）` / `(OS)` / `（内心）` / `（心声）` / `（内心独白）`, or the shot text says 内心独白 / 心声 / inner voice / inner monologue for that line. Phone voices, the system voice 系统 and the narrator 旁白 are not OS (see their own sections).

**2. Shot structure (best case; the storyboard stage should already deliver it).** (IC 947e856, the rule version of episodes 1–5; aligned 2026-11-25 dea54623)
- Consecutive OS lines in the same scene (nobody else speaks between them) go in one shot, shot ≤ 15 s. The OS shot has no spoken line from anyone (no dialogue, no phone voice, no system voice).
- Several OS lines in one shot are the normal case. If spoken lines are mixed in, the OS lines are still written as voice in the prompt and generated by H3: each OS line uses the fixed OS sentence of rule 8 with its `<d>`, word for word the same as the shot's `dialogue` field (see E-004 in section E (人声与台词), revised 2026-11-22; the old “OS goes to post” rule is void). Do not drop any line or rewrite two lines into one. Write it as follows: give each OS line its own time block, written as closed-mouth acting; keep the OS speaker's face and closed mouth visible in every OS block; put any spoken line in its own block **before or after** the OS blocks, never interleaved, and end that block with the speaker's mouth closing. Keep a ≥ 0.5 s silent beat between blocks.

**3. Shot declaration and mouth shape — copy verbatim, only fill the `<…>` slots (IC 4690428 old method, restored 2026-11-24 main seq1320).**
- Shot declaration (once, right after the style/subject lines): `Inner-monologue shot for <Name>: nobody on screen speaks aloud. <Name>'s lips stay pressed tightly shut for the whole shot and never part; teeth never visible; he never sighs, gasps, laughs, grins or breathes through his mouth; all emotion shows in his eyes, brows, head and hands.` (use she/her for a female speaker.)
- Mouth shape (once per OS block): `Mouth shape: <closed-mouth phrase from the table below>.`

**5. Expression must match the meaning of the line.** First decide the line's emotion from what it says, then take the matching row. All mouth shapes are closed, no teeth. Adjacent OS lines (in the same shot and in neighbouring shots) must use different mouth shapes and change at least one of eyes / brows / head / hands; never pick a shape that contradicts the line just to vary it. Rows 11 and 16 only in a subtle version, rarely. The table is section C2 (loaded for every OS shot).

**4. Banned inside any OS block** (they open the mouth): grin, laugh, chuckle, giggle, smile showing teeth, sigh, gasp, pant, huff, exhale through the mouth, sucks in a gasp, mutter, murmur, whisper, mouths, says, tells, replies, answers, talks, exclaims, shouts, yells, cries out, blurts, says aloud, speaks, jaw drops, mouth falls/hangs open, lips part, half-open mouth, bares teeth, bites his lip, sips/drinks, eats. Describe the voice with adjectives (tense, hushed, rapid, rising, trembling, low, bright, biting, almost breaking), never with speech-act verbs. The only verb the off-screen voice gets is `narrates`, and its subject is always `An off-screen male/female inner-monologue voice (S1)`, never the character's name.(IC 4690428 old method, restored 2026-11-24 main seq1320)

**5. Emotion through concrete eye, eyelid and hand actions; 2–3 actions per window (M34 rules 2–3).** Write what the camera sees, like the approved shot: `his pointing right hand hangs frozen in mid-air, eyes round behind his glasses, one eyelid twitching`; `his eyeballs dart left and right, his brows knot together and his right hand slowly sinks`. Choose from: gaze darts / narrows / widens, an eyelid twitches or droops, brows knot / lift, a small nod / shake / tilt, shoulders drop / square, a hand freezes, tightens, sinks or rests. Match the line; neighbouring OS lines change at least one of them. After the window, write the start point (something visible) and the end point `保持到镜头结束 / until the last frame` (M34 rule 4). A shot that is only voice-over gets a visible action chain with a new visible change at least every 3 s; no staring, sitting still or waiting to fill time (M34 rule 5).

**6. No eating, food, chopsticks, spoon, cup or drink actions during an OS window.** Inside an OS window the hands do not pick up, peel, turn, lift or bring food, chopsticks, a spoon, a cup or a glass anywhere; nothing goes toward the face. If the story needs eating or drinking, put it in a time block that does not overlap the OS window, or let the hands rest still (on the table / out of frame). Story props that stay away from the face (a phone held at chest level, a document) are fine.

**7. ### 〔D-002〕 System voice — 系统声写进 `<d>`，由 H3 直出

1. **Who.** A dialogue line whose speaker, with brackets removed, is 系统 / 系统音 / 系统声 / 系统提示 / 系统提示音 / 系统女声 / 系统男声 is a system line. 「系统面板：」 or 「江澈（系统）：」 are not system lines.
2. **Fixed sentence (one per series, copied word for word every time; manual M30 item 1 example).** `An unseen synthetic system voice (Sx) that belongs to no one in the frame, a calm, clear, neutral young female synthetic voice with a faint electronic edge, speaking at a moderate pace, says <d>[Chinese] <complete system line, unchanged></d>.` If the shot binds a system-voice audio asset, add `in the same voice referenced from __MINIMAX_H3_REF_N__` after `pace,`. Never give the system a character's voice reference; never write `<Name> says` for it.
3. **Timing.** The panel (or hint bar) appears in the same second the system `<d>` starts and stays until it ends. 4. **The listener.** Everyone visible keeps the mouth closed while the system speaks: write `<Listener> listens with his lips closed.` (IC 947e856 listener sentence) and act with eyes / brows / head only; no mouth or breath words.
5. **Panel text** follows TR-V04 (the "System UI: short text on the panel" item at the top of this section D): ≤ 2 short lines, ≤ 14 characters each, English quotes, taken from the system line.
6. **Not in scope.** Narration 旁白 and broadcast-style narrators are not changed by this rule; 旁白 stays in post. The workflow manual package r81 that carries the same change is still under review; this section is the IC side only.

## F 一致性（人物、服装、场景、道具、站位、人数）

### 〔F-001〕 Same-scene presence and costume lock — 同场在场人物入画 + 服装锁

H3 only draws people who have a reference and are named in the prompt, and it freely swaps faces and clothes between references. A1 QC lost people and mixed clothes in 7 shots: 5-1 #8/#10/#12 and 19-2 #18 / 20-1 #5 (a seated table-mate was left out of `character_ids` because he had no line, so he vanished), 16-R-V1 #18 (the lead in a crowded wide shot was drawn in another character's dark green shirt), 17-2 #22 (the host got the side-table classmate's orange polo), 20-2 #27 (the speaker was written as "squeezing in from behind", so H3 put the wrong man in the centre and gave him the line). For every shot with two or more people:

1. **Everyone the storyboard places in frame is a reference and is named.** If the scene's blocking map / whiteboard puts a present character inside this framing (edge of frame, soft-focus foreground, back view included), that character must be in the shot's references and must be written into the 0s opening with screen side, facing and state (`lips closed` if silent; in a shot that overlaps an inner-voice window keep their lips closed as in C-001 rule 7, never other mouth words). Never drop a present character just because he has no line. If the framing really excludes him, say where he is (`off screen-left`).
2. **Write a clothing ID for each person (R22 (2))** in `subject_definitions` and again in the 0s opening: colour + garment + hair, copied from the bound costume asset (`__MINIMAX_H3_REF_2__ is Han Zixiao: dark green long-sleeve shirt, slicked-back black hair`). A story state that the bound image does not show is added as words after the ID (`right cheek red and swollen`), see item 11. `fully_preserved` alone is not enough. Only the clothing ID: no faces, ages, materials or accessories. **Asset match (Andy 2026-11-24, 待测):** top, bottom, outerwear and shoes keep the asset's garment type and main colour (asset knee-length shorts → `knee-length shorts`, never `trousers`, `pants` or `jeans`); never add a garment the asset lacks. If the storyboard `visual` disagrees with the asset, write the asset and report the mismatch so `visual` is fixed too; gate COSTUME_ASSET_MISMATCH_PROMPT.
3. **Add the lock sentence** whenever two people could be confused (same sex, similar age, strongly contrasting clothes): `Each person's face and clothing come only from his or her own reference; never move one person's clothing onto another person. Exactly one person in the frame wears <garment>.`
4. **Costume inheritance.** Inside one scene and continuous time, a character keeps the costume reference he wore in the previous shots of that scene (same `costume_ids`) until the story shows a costume change (item 11). Write the same clothing ID, word for word, in every shot; a story state (injury, dirt) is added to it as words and does not by itself change `costume_ids`.
5. **The speaker is already in place at 0s.** Do not make the speaking character "enter / squeeze in / push to the centre" to take his speaking position; put him there from the first frame and state `only <clothing ID> moves his mouth; <others> keep their lips closed` (in a shot that also has an inner-voice window, the silent people stay silent with a closed mouth as in C-001 rule 7).
6. **Wide and crowd shots:** the named leads are at least medium size or in the foreground, with their clothing IDs; extras are described as "other guests" and must not wear a lead's colour.
7. **Who does the action comes from the novel/script, not from a similar-looking extra.** If the visual line names a character (e.g. "支架青年 deletes the clip"), the reference bound for that action must be that character; flag the shot if the binding names someone else.
8. **Headcount lock in every multi-person shot:** besides the count in the first sentence, write once in the body: `Exactly <N> people are in this shot and each of them appears only once: <A> (__MINIMAX_H3_REF_a__) in <clothing ID>; <B> (__MINIMAX_H3_REF_b__), a different man with a different face, <clothing ID>, never in <A's garment>. There is never a second <A> or any look-alike of him in the frame.` N counts only people on screen (voice-only and off-screen people are named as off screen).
9. **No limb without an owner, no second copy of anyone:** every body part at the frame edge or in the foreground belongs to a named, bound person on screen (name the owner, e.g. `Han Zixiao's half-cropped head and right shoulder at the screen-left edge`; never as an over-the-shoulder or foreground-shoulder phrase, which the no-over-the-shoulder rule (section E, "Faceless speaker" item 3) and the gate r71 OFF_OTS_BANNED reject; never use the lead as that half-cropped edge figure while he is also elsewhere in the frame, see ic-lessons TR-B09; examples changed 2026-11-23 IC规则同步 because the old ones conflicted with that rule). Never write a shoulder, arm, hand or back of a head that has no owner in the story, and never a second copy of anyone: `No stray shoulder, hand or arm without an owner enters the frame, and nobody appears twice.` A shoulder-only person with no owner at the edge was drawn as a second lead in ch3 #13. This item does not decide whether an over-the-shoulder framing is allowed; that is section E "Faceless speaker" item 3 and the gate's own OFF_OTS_BANNED.
10. **Per-shot lock inside a scene:** items 2, 8 and 9 apply to every shot of the scene that binds the character, including solo shots, reaction shots and the last shots of the scene, not only the first ones.
11. **Costume change vs. story state:** inside a scene the costume reference and clothing ID stay the same. A **costume change** (changes clothes, puts on or takes off a coat) switches `costume_ids` only from the first shot where the novel or script shows it, and from that shot uses the new clothing ID. A **story state** (injured, dirty, wet, exhausted) is an overlay on the same costume: keep the current `costume_ids` and write the state as words after the clothing ID; bind a state image only when an approved one that matches the novel exists (listed in the trajectory table), and never bind a state image that does not match (a slap gives a red swollen cheek and blood at the mouth, not scratches) — words are better than a wrong image. A prop-holding variant (e.g. "holding the bouquet") is not a costume change: keep the costume and bind the prop. Read the costume-state trajectory table when one exists.
12. **Gaze lock when three or more people are on screen and someone speaks to a person who is not the lead:** `Gaze lock: whenever <A> speaks to <B> or listens to him, her eyes stay on <B>'s face and her head, shoulders and upper body are turned toward him; she never looks at <C> and never looks into the camera lens.` Add where B is on screen (screen side, standing or sitting) from the blocking.
13. **Voice references:** every voice IC attaches gets its own reference line, `__MINIMAX_H3_REF_k__ is <name>'s voice (Sx)`, with Sx in speaking order inside this shot (see Output Rules). A voice reference with no definition line is a duplicate-person risk.
14. **Scene lock:** the first body sentence names the location and two or more visible landmarks. A close-up with a blurred background still names one or two landmarks that remain recognisable in the blur. Use one negation only: `never a plain grey wall or a photo-studio backdrop`. IC always orders references as characters, then scenes, then props. Keep the scene reference early: do not bind background extras who are not needed (or bind a cropped single image, not a grey multi-view board), crop prop images, and never replace a detailed scene image with a rougher one.

## E 人声与台词

### 〔E-001〕 Faceless speaker vs a visible face — 看不见脸的人别和露脸的人同镜开口

H3 gives each spoken `<d>` line to whoever *looks like* the speaker on screen and uses that face's voice, even when the line is tagged with the right `(Sx)` and the voice references are correct. 2026-11-16: shot 17, over-the-shoulder with Jiang Che's back in the foreground, and shot 21, Jiang Che at the door with his back to the camera — in both, the shop owner's face was the only face on screen, and Jiang Che's short reply came out in the owner's voice. Speaking with the back turned is a legitimate shot; the problem is only a faceless speaker next to a visible face. For every spoken line (not OS, not a phone voice from the other end):

1. **A speaker whose face can't be seen may speak only when no one else's face is visible in the shot** — a lone figure from behind, an empty frame, a voice from beyond the door or out of frame are all fine.
2. **If another face is visible, a faceless speaker gets that person's voice.** Fix it one of three ways: the speaker turns his head so at least a profile with the mouth shows while he speaks (`he stops at the door and turns his head over his shoulder, face and mouth in profile to the camera, and says …`); or the line goes into its own shot in which no one else's face is visible; or only the speaker stays in frame. If the storyboard hands you such a shot, change it this way and say so in your report.
3. **No over-the-shoulder shots at all:** never write an over-the-shoulder or 过肩/越肩 framing, including over the shoulder of someone looking at a phone. ### 〔E-003〕 Dialogue window = visible speaking mouth — 台词时间窗与可见开口对齐

H3 places each `<d>` line by the time window it is written in and lip-syncs it to a face it can see. If the window falls while the speaker is still off screen, walking in, turned away or covered, the line is either given to another visible face or heard with no matching mouth. 2026-11-18 (a1 16-R-V1 #18): the female classmate's line was written for 3-6s but she was turned sideways with a hand at her cheek; QC could not confirm her lips. The rewrite said "0-3s nobody speaks; the line starts at 3s; she turns three-quarter to the camera, mouth visible, hand never covers it", and it passed. For every shot with a line:

1. **An on-screen line sits only in a window where its speaker is already in frame, facing the camera at least three-quarter (hard rule: a pure profile or a back view never counts as a visible mouth), mouth clearly visible and not covered (no hand, cup, phone or other person in front of it), and doing a speaking action** (turning or leaning toward the listener, a gesture). Write the start second: `the line starts at <t>s`.
2. **Before the speaker enters the frame, while he walks in, while his back is turned or his mouth is hidden, there is no on-screen line.** Move the line to a window where rule 1 holds, or write it as an off-screen voice (画外音): `an off-screen voice (Sx), <emotion>, says <d>[Chinese] …</d>; nobody on screen moves their lips`, or leave the window without dialogue.
3. **Say when a window is silent:** `0-3s (no dialogue: nobody says a word in this window)`. When a shot has one line, name it as the only dialogue window.
4. **Inner monologue (OS), phone voices from the other end and the system voice are always off-screen voices** and follow the OS and faceless-speaker sections above; they need no visible speaking mouth, and every visible face keeps its lips closed during them. (IC 947e856 wording)
5. **Check before you hand over:** for each `<d>` line list window -> speaker -> in frame and at least three-quarter to the camera (not pure profile, not back view)? -> mouth visible? -> speaking action? Any "no" must be fixed, not just noted.

### 〔H1-003〕 Camera, one-take and fight shots — 机位运镜与一镜到底

Applies to every shot's `video_prompt`. Read the shot's `camera` field first: the storyboard stage marks it `FIXED`, `MOVE`, `ONE-TAKE` or `CUT@Ns` (see sd-storyboard-engine「机位运镜与一镜到底」). If the field has no mark, treat it as `FIXED` unless the storyboard text clearly describes one continuous camera path. The inner-monologue rules, the Q-version / VFX rules, the opening "video begins already inside…" sentence and the expression switches all stay in force; this section never overrides them (an OS block stays a frontal close-up, steady or slow push-in; the 1–2 s of a Q-version insert keeps the camera still).

**1. One camera instruction ≈ one cut.** H3 reads every new camera verb (`pushes in`, `pans`, `whips`, `cuts to`, `orbits`) as a new shot. So:
- `FIXED`: one sentence, once: `The camera holds a fixed position (static shot) for the whole shot.` Time blocks after that describe only action and sound.
- `MOVE`: one small, slow move written once; no second camera verb. Sentence form (v4.4): item 1 of `fight-v44.md`, loaded with skill_reference(name="h3-prompt-writing", ref="fight-v44.md").
- `ONE-TAKE`: one continuous move, stated once at the start, with at most two continuation sentences at path nodes, each phrased as the same move continuing.
- `CUT@Ns`: write the cut only at the marked second: `At <N>s, the camera cuts to <new framing, side, distance>.` No other camera verbs in between.

**2. One-take template (`ONE-TAKE`, 8–15 s).** Fill the 〔…〕 slots; keep everything else.
> `This is one continuous take with no cuts from the first frame to the last. 0s: 〔framing〕, the camera starts 〔behind / beside / in front of〕 〔who〕, about 〔N〕 metres away at 〔chest / eye / knee〕 height; 〔who〕 is on screen-〔left/right/centre〕 facing 〔direction〕, 〔who〕 is on screen-〔…〕 facing 〔…〕; 〔prop〕 is in 〔whose〕 〔left/right〕 hand. 0-〔t1〕s: 〔action〕; the camera 〔follows / tracks alongside / pushes forward〕 at 〔slow / steady / walking〕 speed. 〔t1〕-〔t2〕s: 〔action〕; the same unbroken move carries the camera past 〔landmark〕 〔toward / around to the right side of〕 〔who〕. 〔t2〕-〔end〕s: the camera slows and settles into 〔end framing〕 of 〔who〕, 〔positions and facings at the end〕; 〔held micro-action or dialogue〕. The camera never passes through walls, glass, furniture or people.`
- Every time block still needs a visible body action (a moving camera does not count as action). The camera may keep drifting while a character freezes for a beat — that contrast reads well; do not make both camera and character violent at once.
- Never write `cuts to`, `whip pan`, `quick cuts`, `dynamic camera`, `shaky cam throughout`, or a new camera verb in every block inside a one-take shot.

### 〔H2-001〕 Q-version (chibi), exaggerated VFX, slang and homophones — hard rule

The show's baseline is photorealistic live-action. A Q-version insert is a short, extreme-emotion exception, not a style change for the whole shot. Two presentation modes follow the 2026-11-11 definition: a chibi miniature beside the character, or a brief chibi head swap. The 2026-10-02 ban on head-swaps is revoked. A brief head swap is allowed; the live-action face must return within 1–3 seconds.

**Slang, jokes and homophones (items 10, 11 and the 谐音 example) moved verbatim to volume H2L on 2026-11-25; read H2L when the shot has a slang / joke / homophone 【表现】 line.**

**Items 0 and 0b and the v4.4 rule moved verbatim to volume H2C (2026-11-25); H2C is read with every 【表现】 shot.**

**1. When it appears.** Only if the shot has a `【表现】…Q版·方式一` or `【表现】…Q版·方式二` line. The storyboard places these only on an extreme-emotion beat (cognitive shock, sudden windfall, collapse, or extreme joy), one mode per beat, at most two per episode. Ordinary surprise, a normal smile, ordinary anger, and serious or sad beats (a breakup, betrayal, grief) get real acting only — no chibi, no cute effects.

**2. Mode 1 — chibi miniature beside the character (positive wording).** Write a short visible action, then a return. The chibi's motion must be exaggerated and unrestrained — a sliding kneel, clutching the belly laughing, clutching the head with both hands, or both fists pumped in the air. Never a meek standing pose, a cute idle, a slight nod, or a kawaii wave.

> For about 1–2 seconds, a small super-deformed chibi miniature of <Name> pops in beside <Name>'s head, about as tall as his real head, matching the hair colour and outfit colours of __MINIMAX_H3_REF_N__, with a cool deadpan face, and [one exaggerated unrestrained action: a sliding kneel / clutching the belly laughing / clutching the head with both hands / both fists pumped in the air]. The live-action <Name> and the real scene stay fully visible and photorealistic; the chibi never covers his eyes, mouth, the key prop, or the system panel. Then the chibi disappears, and the shot stays live-action.

**3. Mode 2 — chibi head swap (positive wording).** Write the swap and the revert in the same shot:

> For about 1–2 seconds, <Name>'s head briefly becomes a super-deformed chibi head matching the hair colour of __MINIMAX_H3_REF_N__, with [specific expression, e.g. a dead-fish-eye look of shock, the head cocked hard to one side], while his live-action body, clothes and the scene stay photorealistic. **3b. Chibi reference asset (hard rule, v4.2).** Every chibi shot must have the character's chibi design asset 「<Name>·Q版设定」 bound in the shot's props, so it arrives as its own reference image (label like `江澈·Q版设定（道具）`) next to the live-action character image. Text such as "use it only as a layout reference; do not take its lighting" does not override it. Before binding a scene reference, look up its class in the project's scene time-and-lighting table (built by looking at the images; the asset description's 状态 field is not reliable): daylight from above / low-angle warm sun / night / interior artificial light / multi-panel board; lamps lit or not; indoor, outdoor or car.

1. **Blocking errors are only clear conflicts.** (a) Day and night reversed: a night shot bound to a daylight or warm-sun image, or a day shot bound to a night image. (b) The image has lamps lit and the shot gives no reason for them: the shot says the lights are off, or it is a daytime exterior and the shot never mentions lamps. (c) Indoor and outdoor light sources that cannot match: an exterior shot bound to a purely artificially lit interior image, or an interior shot bound to an exterior image.
2. **Explainable differences are warnings, not unbinding.** Warm vs cool, early morning vs late afternoon, "morning" vs a low warm sun, lamps on in an interior: keep the image and rewrite the prompt's lighting to match it (e.g. the balcony image has a low warm sun, so write `early-morning warm low sun with long shadows`). Never write lighting that contradicts the bound image.
3. **Inherit first.** If shots of the same scene have already been rendered and accepted with a scene image, later shots of that scene bind the same image and describe the same light, unless that image has a blocking error for this shot.
4. **Fixing a blocking error.** (a) Bind another final image of the same place whose time and lighting match. (b) Otherwise unbind the scene image and write the layout in the prompt as text, inside `detailed_description` after the style and lighting sentences: `Location (no scene reference image is used for this shot; build the place from this description): <the place, its main surfaces and furniture, depth, and what is on screen-left / screen-right>.` Remove the scene's `subject_definitions` and `retention_analysis` lines and every `(__MINIMAX_H3_REF_n__)` that pointed at it, renumber the remaining references in binding order, and change "identity and location references only" to "identity references only". Keep the shot's time-of-day and lighting sentence. Never keep a conflicting image with a "layout reference only" disclaimer.

### 〔J-002〕 Close framing on a wide scene reference — 场景图是全景、本镜是中景/近景/特写

When the bound scene reference image is a wide or establishing shot and this shot is a medium shot, a medium close-up or a close-up, H3 copies the whole wide layout from the image and shrinks the characters to fit it. For every such shot:

1. **The shot-size sentence comes first and is explicit.** It is the first sentence of the prompt (free-text prompts) or the first sentence of `summary` and of `detailed_description` (Ref2VA sections; `subject_definitions` stays first). Name the size, the body crop and the face size, e.g. `Medium shot, framed from the waist up; each face is about one quarter of the frame height.` / `Medium close-up from the chest up; the face fills about one third of the frame height.` / `Close-up of Jiang Che's face; the face fills most of the frame height.` (中景/腰部以上/脸约占画面高度 1/4). Do not open with the location.
2. **The scene reference describes only the background visible behind the character.** Its definition says what this framing shows behind and beside the character (e.g. `__MINIMAX_H3_REF_2__ is the background behind Jiang Che: the green wall with the gold peony relief`), not the whole room.
3. **Retention is "background only / partially".** Ref2VA: `__MINIMAX_H3_REF_n__: partially_preserved - background only: <what is visible behind the character>`. Free text: `use __MINIMAX_H3_REF_n__ for the background only, partially`. Never `fully_preserved` for the scene in such a shot.
4. **The layout list keeps only what this shot can show.** Keep the items behind or next to the character in this framing; drop the far door, distant tables, the ceiling chandelier and anything else that cannot be in frame at this size.
5. If the scene image itself is already a medium or close view of that spot, rules 2–4 are already met; rule 1 still applies.

## B2 生成模式、全参考与多段（冷门）

### 〔B2-001〕 Workflow

1. Identify the input mode: T2VA, I2VA, FL2VA, L2VA, or full-reference Ref2VA.
   - If the model supports image input, view each unique character/scene/prop reference image ONCE via `view_asset` and reuse it across shots — do NOT re-view the same image per shot; use `view_shot_references(shot_id)` only when a shot introduces an asset you have not yet seen.
2. For base text/keyframe modes, read `references/base-en.txt` and follow its final prompt structure.
3. For full-reference mode, read `references/ref-en.txt` and follow its six-section rewrite format.
4. Preserve the exact field names, section order, labels, and timing notation from the selected guide.
5. For a multi-segment short film (hardware limits prevent one long H3 generation), compile from a storyboard contract instead of writing prompts by hand — see “Storyboard-Driven Multi-Segment” below.

### 〔B2-002〕 Base Modes

- T2VA: build the full audiovisual timeline from text.
- I2VA: start from the first frame and develop forward from it.
- FL2VA: describe the continuous path between the first and last frames.
- L2VA: infer a plausible opening and converge to the supplied last frame.

Use `integrated_multimodal_description`, `overall_soundscape`, and `non_diegetic_music` in the order shown in `references/base-en.txt`.

### 〔B2-003〕 Full-Reference Mode

Ref2VA rewrites use `subject_definitions`, `summary`, `retention_analysis`, `detailed_description`, `overall_soundscape`, and `non_diegetic_music` in that order. Reference labels stay consistent across all sections. In `subject_definitions` each subject is defined by **name + role**; the only appearance words allowed are the clothing ID that R22 below requires (multi-person scenes and story states). No other look description (see R22; this narrows `references/ref-en.txt` §2.1).

Read `references/ref-en.txt` for label rules, retention analysis, and complete examples.

### 〔B2-004〕 Storyboard-Driven Multi-Segment

When H3 cannot generate the whole film in one pass, generation is split into short segments chained by the previous segment's last frame. Drive this from a **data contract** rather than hand-copied prompts, so segments stay consistent and none of them silently repeats another.

> **Runner note (this repo):** the in-app Agent has **no shell tool** — it cannot execute `python scripts/...`. Write `storyboard.json` with the domain tools (`set_storyboard` / `update_shot`); the `scripts/*.py` compiler helpers are for a **human/offline terminal**, not a runtime step. Do not attempt to run them.

Offline compiler steps 1–5 and their notes (author `storyboard.json`, compile, gates, segment typing) are for a human/offline terminal only; they now live in `references/offline-compiler.md`. The in-app Agent does not need them.

### 〔B2-005〕 Tips for Better Results
- Always match the total duration of the description to the requested video length (2–15 seconds), driven by content rhythm: a single short line of dialogue needs only 2–4 seconds — do not pad short shots to 10+ seconds.
- Keep reference labels consistent (e.g. `<Picture 1>`, `<Video 1>`, `<Audio 1>`) across every section.
- Prefer concrete visual and audio details over abstract words like "cinematic" or "beautiful".
- Give every spoken line a concrete delivery description (emotion + pace + tone) with real intensity so the speech carries feeling, speed variation, and emotional thrust instead of a lazy flat monotone; pair loud/urgent delivery with big physical actions. (For inner monologue: big actions of eyes, brows, head and hands only; the mouth stays closed.)
- When using keyframes (I2VA / FL2VA / L2VA), clearly state how the first and/or last frame connects to the timeline.
- **注意事项必读：** 写或改镜头前调用 skill_reference(name="h3-prompt-writing", ref="注意事项.md") 读全文——镜头渲染只读 `video_prompt`（改动作 / 时间轴必须改 `video_prompt` 的英文时间轴）；多人同框逐人写区分特征并写明「几个人长相各不相同，不是姐妹」。

## Q 审片

### 〔Q-001〕 【审片】逐镜要看的已验证项

审片（成片、预览、抽帧）时逐镜对下面各项，看到就按原规则记问题，写清类别：

1. 同一个人在画面里出现两次（含前景半截头肩、画面边缘、倒影）；在场的人突然消失或突然多出一个人（TR-B03）。
2. 同场同一人物的衣服变了，而原著这里没换衣服（TR-B02）。
3. 脸部状态（眼袋、疲态、气色）和剧情节点对不上（TR-V01）。
4. 系统说话时光幕没同秒出来；光幕字超过两行、看不清、带「」『』【】；系统声没念出来（TR-V04、系统声）。
5. 特效为了出效果切了近景（TR-V05）；交易少了步骤或用了替代物（TR-V06）；打戏反应慢、有人发呆、人群飘着后退（TR-V08）。
6. 人物为了听心声停下动作；心声镜里嘴在动（TR-V09、心声节）。
7. 同场相邻两镜人物左右位置互换、坐变站没有动作（TR-V10）。
8. 电话那头的声音中途变了（TR-V02）；关键道具变大变小（TR-V03）；念出来的数字读法不对（TR-V14）。
9. 整个画面变成了参考图、三视图或灰色棚拍背景（TR-B01）。

审片流程：问题分大、中、小，只有大问题（影响主线、换人换衣、同一人出现两次、声音给错人、参考图泄漏）进本轮重出，其余记账（TR-A02）；已经通过的集不整集重出，只重出有问题的镜（TR-H01、TR-S01）。

### 〔Q-003〕 【待测】【审片】字幕三项：错字、重叠、和语音不符（G18，txt L48、L70、L132、L166、L168）

### 〔Q-004〕 【待测】【审片】重出的片按新片审，审完每个新片都要有选片结论（G19、G27，txt L205、L215、L222、L223）

  4. 例外：音乐是镜头自己带出来的（去掉 BGM 轨，单听这一镜的原声里就有音乐），记为该镜的问题，按 B-001 改稿重出。
  5. 配乐问题和字幕问题一样，当轮重新合成后再交付（同 Q-003 第 5 条）。
- 可用短句：
  - 检查句：「配乐整集听完：无卡顿、无跳拍、无重复段、底噪连续、台词清楚。」

### 〔Q-006〕 【待测】【审片】剧情看不看得懂：动作有没有原因、台词听不听得懂、场和场接不接得上（G23，txt L25、L57、L59、L60、L65、L71、L99、L116、L131、L133–L136、L146）

- 原则：审片的人要站在没看过原著的观众位置上看。这类问题出在剧本和分镜，重抽同一份提示词改不掉。本条细化 Q-002 里「动作或台词不合原著（G23）」一句，Q-002 不变。
- 适用条件：审成片或预览时；审片的人。先不看原著和分镜通看一遍，再对原著查有疑问的地方。
- 正确写法：
  1. 动作：人物做的每个大动作（起身、坐下、走开、推打、鼓掌这类）看得出原因，而且原著里有。看不出原因或原著没有的，记下。
  2. 台词：每句台词听得出是谁对谁说、说的什么事。听不懂、不知道在回应什么、意思和原著不一样的，记下原句。
  3. 语气：语气和人物这时候的处境相符（服软的不意气风发）。
  4. 衔接：换场以后知道人物在哪、怎么来的；一句回应的台词之前，看得到它回应的那件事；中间没有跳过观众需要知道的事。
  5. 登记时写清该谁改：台词怎么写、语气标注归剧本（adapt-rules R-002）；动作、进场、衔接镜归分镜（adapt-rules S-016、S-011）；分镜是对的而提示词多写、换了动作或语气写反，归提示词（L-004）；分镜和提示词都对、只是这一次出片演错了，才直接重出。前两种先改稿再重出，不拿原提示词重抽。
- 可用短句：
  - 检查句：「不看原著通看一遍：动作都有原因；台词都听得懂；语气合处境；换场接得上。」
  - 登记句：「〔时间点〕〔动作没原因／台词听不懂／语气不对／场间接不上〕：〔现象〕；应为〔按原著的写法〕；归〔剧本／分镜／提示词／出片〕，处理：〔改稿后重出／重出〕。」

### 〔Q-007〕 【待测】【审片】每句台词是不是对的人说的（G13，txt L84）

- 原则：台词挂错人，剧情就变了味。Q-001 已把「声音给错人」列为大问题，那是声音和人对不上；本条查的是这句话本来就不该由这个人说。Q-001 不变。
- 适用条件：审有两个以上人物在场、有出口台词的镜时；审片的人。

  1. 逐句看：成片里这句话是谁说的，对照这一镜 `dialogue` 的说话人，是不是同一个人。
  2. 有疑问的再对原著：这句话在原著里是谁说的。`dialogue` 的说话人和原著不一样，也算挂错人。
  3. 重点看这几种镜：邻桌、路人、店员这类小角色有台词的镜；一镜里三个人以上的镜；说话人在背景里或在画面边上的镜。
  4. 登记时写清错在哪一步、该谁改：`dialogue` 的说话人和原著不一样，或说话人没绑进这一镜，归分镜（adapt-rules S-017），先改稿补绑再重出；`dialogue` 和绑定都对、提示词把这句写到了别人名下，归提示词（E-011）；稿子都对、只是这次出片由别人说了，按「声音给错人」直接重出。
  5. 这一项算大问题，进本轮重出。

### 〔Q-008〕 【待测】【审片】物理穿帮和机位拍错空间（G23，txt L141、L151）

- 原则：人从栏杆里穿过去、戏在车里却拍车外，观众一眼就出戏。这两种多半是分镜没定清楚，光重抽不一定改得掉，登记时要分清该改哪一步。
- 适用条件：审有人物走动、过门、上下楼的镜，和戏在车内、电梯、隔间这类空间里的镜时；审片的人。
- 正确写法：
  1. 穿帮：人或东西穿过实体（栏杆、墙、玻璃、门、柜台、家具、车身、别人）；脚没踩在地面或台阶上；手里的东西穿过身体或桌面。看到就记时间点和穿过了什么。
  2. 机位空间：对照分镜，这一镜的机位该在里面还是外面、该对着谁。戏在里面而画面拍的是外面，或对着的不是戏里的人，记下。
  3. 登记时写清归哪一步：分镜没写机位在哪个空间、路线本身走不通或没必要地用了楼梯和门，归分镜（adapt-rules S-018）；分镜写了而提示词没落下去，归提示词（H1-004）；两边都写清了、只是这次出片穿了，直接重出。
  4. 同一镜重出过仍然穿帮：不再原样重抽，退回分镜按 S-018 第 4 条避开那个结构（改走平地，或切到人已经到了）。
- 可用短句：
  - 检查句：「走动、过门、上下楼的镜逐镜看：没有人或物穿过实体，脚在地面或台阶上；有里外之分的镜机位空间和分镜一致。」

  - 登记句：「〔时间点〕戏在〔车内〕，画面拍的是〔车外〕，归〔分镜／提示词／出片〕，处理：〔 〕。」

### 〔Q-009〕 【待测】【审片】场景看着像不像它该是的地方（G08，txt L100）

- 原则：场景像别的场所，问题在场景图，不在这一镜。原样重抽还是照那张图画，改不掉；要回到资产换图。本条细化 Q-002 里「场景用途不对」一句，Q-002 不变。

  1. 不看分镜和资产名，只看画面：这是什么地方。看着像的地方和剧情里的地点不一样，记下「像什么」和让人这么觉得的那样东西（例如某种隔断、窗口、柜台）。
  2. 再对常理：这类场所现实里会不会有这样东西。不会有的，算场景不符。

  4. 归资产的，同一张图的所有镜一起登记，不只记被看出来的这一镜；换图后这些镜按导出合成通用规则 X-007 列旧片清单，逐镜定重出还是保留。

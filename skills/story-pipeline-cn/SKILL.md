# 小说剧本分镜流水线（story-pipeline-cn）

单包模块化技能，覆盖从**小说 → 剧本 → 分镜**的完整创作链。`SKILL.md` 只做薄路由；分步指令在 `references/`，输出模板在 `templates/`，文件批处理脚本在 `scripts/`。执行前须先 `Read` 对应模式文件。

## 入口：模式选择菜单（首次激活必显）

**规则**：技能被激活时，若用户**未明确指定模式**（即未提供以下任一类明确意图：小说/剧本文件路径、或明确说「转剧本/出分镜/拆镜头」等），**必须先向用户完整展示下方菜单并请其选择，禁止自行假定模式**。即便已提供材料但意图不清，也先展示菜单确认，再进入对应模式。

**展示方式**：优先用交互选择控件列出 3 项（A–C）；若该环境不支持控件，则以纯文本列出并请用户回复字母（A–C）或编号。菜单文本如下，可直接呈现给用户：

```
请选择要运行的模式（A–C）：
A · 小说转剧本  — 选定素材→三幕结构→场景剧本成稿（.md），适合「有小说想改编」
B · 剧本转分镜  — 现成剧本→分镜表+角色人设卡+AI绘图/视频Prompt（.md/.json），适合「已有剧本想可视化」
C · 小说转分镜  — 小说直拆→分镜脚本+角色特征卡+场景特征卡（一键，支持文件批量），适合「快速出分镜/喂给画图模型」
```

选定后，按下方「三模式 + 一条流水线」定位到对应 `references/` 入口执行。

## 三模式 + 一条流水线

| 模式 | 何时用 | 主入口 |
|------|--------|--------|
| **A · 小说转剧本** | 有小说/素材，想改编成可分镜的文学剧本 | `references/novel-to-script.md` |
| **B · 剧本转分镜** | 已有剧本（.md/.txt），想拆分成镜、出人设卡与 AI 提示词 | `references/script-to-storyboard.md` |
| **C · 小说转分镜** | 想跳过中间剧本，直接把小说拆成镜头与角色卡（含批量文件模式） | `references/direct-storyboard.md` |

### 工作链流水线

```
A(小说转剧本) ──→ B(剧本转分镜) ──→ [可选接下游图像/视频生成工具出图出视频]
                       ▲
C(小说转分镜) ＝ A+B 的合并快路径（跳过中间剧本文件，直出分镜 + 下游生成工具兼容 JSON）
```

- 提供**小说/素材**且要改编成剧本 → 模式 A
- 提供**现成剧本**且意图为「出分镜/拆镜头」→ 模式 B
- 提供**小说**且意图为「直接拆镜头/出角色卡/喂画图模型」→ 模式 C（快路径）
- 任一模式产出的 `storyboard.json` 均可直接喂给下游图像/视频生成工具（见 `references/workflow-chain.md` 的桥接说明）

## 心声（OS）镜铁律（2026-11-16 新增 · 治「心声镜头人物张嘴对口型」）

心声 = 角色没说出口的内心独白，画面里的人**不许张嘴**。视频模型会给台词自动对口型，所以分镜层必须先把心声标出来、拆干净，下游的 h3-prompt-writing 才能按心声规则写提示词。

1. **标记**：心声在 `dialogue` 和 `sub_shots` 里一律写成 `角色名（OS）：原文`（例：`江澈（OS）：这得有1000克吧？！`）；普通对白写 `角色名：台词`。电话声、系统声、旁白不是 OS。原文一字不改。此处「原文」指**已锁定的剧本台词**。若剧本层（`references/novel-to-script.md`「表现手段入口 · 剧本层」）已把原著「卧槽」升级为显示字「我cy！」并附 `[配音：我去！]`，则 `dialogue` 逐字写显示字，实念字按 `sd-storyboard-engine`「夸张表演、特效与 Q 版」甲·4 用 `【表现】…配音替换` 交给提示词；不得改回原脏话。
2. **单独成镜**：心声镜里不能有任何人开口（含对白、电话里的声音、系统女声）；对白、系统音放到相邻镜头。
3. **同场心声合镜**：同一场景里连续的心声（中间没有别人开口）合进同一镜，镜长 ≤15 秒。
   - **心声原文一字不改（2026-11-16 v2）**：**禁止**删字、改字、换词、把两句改写成一句、改写语序，也不许改数字写法（原文是「3500」就写「3500」，原文是「1000克」就写「1000克」，不改成「三千五」「一千克」，反之亦然）。
4. **机位（对本技能其他机位规则的例外）**：心声镜用正面或近正面（±30° 以内）的近景/特写，**嘴在画面中间、看得清**；不用「捂嘴、背身、远景、低头、杯子挡嘴」这类遮嘴写法。心声镜里只有说心声的这一个人，别人在场只能是虚焦/背影/侧影且不说话。
5. **表演**：每句心声在镜行里写「情绪 + 闭着的嘴型 + 眼/眉/头/手动作」，嘴型必须是闭着的、不露牙（抿成一线、憋笑、撇嘴、单边嘴角上翘、咬牙、嘴角下撇、苦笑抿唇……），贴合这句心声的意思；相邻两句心声嘴型不同。禁止写「张嘴、笑出声、叹气、倒吸凉气、嘟囔、咧嘴、捂嘴、含着杯沿」。
6. **不写台账词**：不要在镜头描述里写「台词：无」「（无对白）」「（沉默）」这类字样，下游会被念出来；没有台词的镜头 `dialogue` 留空即可。
7. **连排**：整章不要连续 3 镜都是心声。

## 表现手段入口（2026-11-16 v4 · 取代 v3.1「表演、特效、Q 版优先于心声」）

四类手段：**Q 版插入、夸张特效、网络流行语与过审谐音、段子与接梗**。口径：表情表演 > 特效 > Q 版 > 心声。能用眼神、动作、对白、闪回或特效让观众看懂的，不要改成内心独白；只有完全无法演出来时才用心声。

**先看开关（v4）：** 任务文本里若有「本项目表现手段开关」一段，先读其中四项：**Q版插入、夸张特效、网络流行语与谐音、段子与接梗**。被关掉的手段本章一律不用，本节里和它相关的条目、配额、选择表那一列都不适用（改用真实表演；台词保持原著平实说法）。没有这一段，视为四项全开。开关只管「能不能用」：开着也要按选点标准和上限来，不是必须用。**（v4.4-B）开关段里那句「不是每章必须用，宁缺毋滥」说的是不堆砌：本章没有够格的点可以不用；有够格的点（见各层手册里的「本剧落点」）却一处不落，算漏做，不算克制。**

**Q 版门槛与名额（v4.5，2026-11-16 Andy 定；优先于本节和 `sd-storyboard-engine` 里 Q 版的旧配额与「漏做」口径）：** Q 版默认不用。只给全章最极端、而且 Q 版明显比真人表情加动作更好看的那一处；其余「极端」点（包括剧本写了「可选：Q版」的）一律真人表演，Q 版不算漏做。每章最多 1 处；第 2 处只在两处都是全章顶点、方式不同、相隔 ≥3 个场次且成片相隔 ≥90 秒时才允许。上一章用过的 Q 版动作或表情，本章不重复。方式一（身旁小人）给独处憋笑的狂喜，方式二（换头）给被规则当头一棒的无语，同一拍只用一种。该镜 `props` 必须绑定素材库里已有图的「角色名·Q版设定」；没有或没图就不出 Q 版、改真人表演，并在 `report` 写明缺哪个角色；不得新建、生图，也不得凭写实参考自由发挥 Q 版造型。Q 版镜头的【表现】行必须写明具体表情（眉眼和嘴的样子，例：眼皮半垂、眼神发直、嘴抿成一条线），不写 shock、surprised、「震惊」这类笼统词；Q 版设定合板只作造型参考，不得照抄合板里的表情格。

分层入口（每层都要做，缺一层算没做）：

| 层 | 在哪 | 做什么 |
|---|---|---|
| 剧本 | 本技能 `references/novel-to-script.md`「表现手段入口 · 剧本层」（IC 写剧本时必须 `skill_reference` 读它） | 标 `[表现点 Pn｜…]` 候选点；局部升级台词（流行语 / 谐音 / 段子），留 `[台词升级 Ln｜…]`；谐音句写「显示字」+ `[配音：实念]`；（v4.4-B）吐槽位的 `可选` 必须含流行语或段子；流行语与段子合计 ≥1 或写明理由；原著自带的自嘲不删 |
| 分镜 | `sd-storyboard-engine`「夸张表演、特效与 Q 版」 | 对每个候选点按选择表定手段和方式，写 `【表现】` 行；做全章用量台账与自检；（v4.4-B）按「本剧落点表」逐手段核对落点，特效与 Q 版同段接力 |
| 提示词 | `h3-prompt-writing`「Q-version (chibi) and exaggerated VFX」 | 把 `【表现】` 落成英文可见画面；`<d>` 用配音实念字 |

拆分镜（模式 B / C，含 IC 长镜头聚合）时：剧本里的 `[表现点]` / `[台词升级]` / `[配音：]` 行都不是台词，不进 `dialogue`；每个 `[表现点]` 都必须在分镜台账里有去向（用在哪一镜，或不用的理由）。**对白栏写屏幕字幕显示的字（如「我cy！」）；视频提示词 `<d></d>` 写实际配音（如「我去！」）；两者只在过审谐音句上不同，其他句子一字不差。**

分镜层同时守住：镜头 0 秒已在场景内，人物照参考图还原长相与服装，参考图、设定图、三视图本身不整张贴进画面；系统光幕悬浮在身侧或面前半空，不贴身体；金光眼、卡姿兰大眼单独做成眼部大特写，和台词、心声错开，并写满整镜时长或在同镜内拉回到他的脸和动作，不留空镜；Q 版小人动作夸张、浪荡（滑跪、捧腹、抱头、双拳振臂），不乖不萌。**（v4.4-B）特效与 Q 版可以在同一个爽点段里接力（不同镜、中间隔一个真人镜），不再按「相邻夸张一律 ≥45 秒」互相挤掉；方式一、方式二、金光眼、卡姿兰、流行语、段子六项在台账「落点核对」里逐个写去向；手段取舍不写进连续性记录。**

**正例：** 「这得有1000克吧」的震撼，先写一镜眼部大特写：虹膜迅速变成发光的金色，向外喷出金色光芒和粒子；能看懂就不再叠一句解释性心声。
**反例：** 每个情绪点都改成大段 OS，画面只剩一张呆脸；或整章没有一个表现点，爽点全靠心声念出来；或六种手段里只落了谐音和一处特效就收工（v4.4-B）；或每章都找地方塞 Q 版（v4.5）。

## 参考图照着演，不整张贴进画面（2026-11-17 · 治成片闪全屏三视图）

参考图是用来还原人物身份和造型的，人物要在场景里活起来，用参考图的长相和服装去演本镜动作。

已交付 EP1–EP11 实测：H3 常在镜头开头（少数在结尾）把参考图原样直出 2–31 帧。闪出来的不是剧情画面，而是灰棚或白底的全身站姿、左特写加右三视图合板、服装商品图、Q 版合板，或道具多角度板。根因是人物、服装、道具的参考图本身就是这类设定板，系统又把原图整张送给 H3。

硬规矩（分镜和视频提示词都必须守；`h3-prompt-writing` 现有手册已到字数上限，细节以本节为准）：

1. 每一镜 0 秒必须已经在剧情场景里。禁止先出现参考图、设定图、三视图、灰棚或白底全身站姿、服装商品图、Q 版合板、道具多角度板。结尾同样不得切回这些板。
2. `__MINIMAX_H3_REF_N__` 照参考图还原长相与服装，不整张贴进画面。不要写 show the reference image、character sheet、turnaround、catalog photo、white background portrait。开场第一句写清场景、人物位置和景别。
3. 提示词时间轴开头加一句（可略作改写，意思不能丢）：`Use the reference images to recreate the characters' faces, hair and outfits inside the scene; never paste a reference board, turnaround or studio portrait onto the screen as its own frame. The shot starts already inside the scene.`
4. Q 版照 Q 版合板的造型来演，合板格子或单人白底设定图不整幅切进画面。

（代码层另改，不在本手册完成：送给 H3 的人物/服装参考改为单人正面或左特写裁切；出片后自动检测并裁掉棚拍板帧。）

## 环境与约定

- **路径**：所有路径使用绝对路径，`/` 作分隔符。`<skill_root>` 指本技能根目录。
- **输出落盘**：所有产物写入用户指定的项目目录（默认 `<skill_root>/outputs/<作品名>/`）；先建目录再写文件，中间文件一律保留不删。
- **中文优先**：场景头、对白、提示词草稿默认中文；面向画图/视频模型的 `image_prompt` / `video_prompt` 须在阶段末翻译为英文（见 `style-guide.md` 与 `output-schemas.md`）。
- **人设一致性**：全链路角色名须唯一且稳定；模式 C 的脚本会自动建立 `姓名 → CHAR_xxx` 映射，供下游生成工具直接消费。
- **门控**：模式 A/B 在成稿关键节点建议展示片段请用户确认；模式 C 为批量处理，默认一次出全稿，但长文本建议在 `scripts/extract_storyboard.py` 中分段。
- **下游桥接**：本技能只负责「文本→结构化分镜」，不调用任何画图/视频 API；出图出视频请用下游图像/视频生成服务。桥接字段对齐见 `references/workflow-chain.md`。

## 机位运镜、打斗与一镜到底入口（2026-11-16 新增）

拆分镜（模式 B / C，含 IC 长镜头聚合）时，每条分镜的 `camera` 字段先标镜头形态 FIXED / MOVE / ONE-TAKE / CUT@Ns，再写景别和机位；打戏、追逐、走位按 sd-storyboard-engine「机位运镜与一镜到底」拆冲击镜和反应镜、挑一镜到底的位置、写段内时空白板；写视频提示词时按 h3-prompt-writing「Camera, one-take and fight shots」落地。模式 C 的「长镜头聚合」把同一场景的连续动作和对白合成一条分镜，这一条的镜头形态照样要标；镜内要切必须写「切到」。


## IC 执行约定：分镜写完必须接着写视频提示词（2026-11-17）

**加载阶段**：IC「生成分镜 / 自动生成下一章分镜」文本任务（`storyboardOnly` / `renderDisabled`）会先 `skill(story-pipeline-cn)` 拆分镜；本节约束的是 `set_storyboard` 写入之后、任务汇报完成之前。出片阶段不在本技能范围内。

**要做的事**：

1. 本章分镜用 `set_storyboard` 写入后，必须把每镜的 H3 `video_prompt` 写进数据库，不要等到出片阶段再写。
2. 优先在 `set_storyboard` 的同一条分镜对象里带上 `video_prompt`。来不及写的，用返回值里的 `shot_id：第N镜=id` 调用 `update_shot(shot_id, {video_prompt})`。
3. `video_prompt` 必须先 `skill(h3-prompt-writing)`，按它的 `__MINIMAX_H3_REF_N__` 规范落地；本技能 `references/` 里旧的「只写英文运动、不写外貌」草稿不能代替 H3 正文。
4. 不要因为 `list_shots` / `get_project` / `list_assets` 的结果被转存成文件就放弃——以 `set_storyboard` 返回的 `shot_id` 为准，不必再翻文件。
5. 本阶段不要调用 `generate_assets_batch`、出图、出视频（这些工具会被跳过）。待做的资产图和音色由系统在文本收尾后自动排入 IC 自己的视频队列，排在正在出的视频后面，不会另起提交器，也不会挤掉正在跑的出片任务。

**和现有规则冲突时**：

- 与 `references/workflow-chain.md`「本技能不调用画图/视频 API，交给下游」不冲突：下游出片仍是后续阶段，但 `video_prompt` 必须在本阶段写入数据库。
- 与 h3-prompt-writing 的提示词格式冲突时，以 h3-prompt-writing 为准。
- 与「只给 `has_prompt=false` 的镜头写视频提示词」一致：已有提示词的镜头不要覆盖。

**下游字段**：只写 `shots.video_prompt`。不改剧本 `script`、不改镜号 `idx`、不碰已有 `video_path`。`set_storyboard` upsert 时若未传 `video_prompt`，不得清空该镜已有提示词。

## 注意事项（2026-11-18，来源：总导）

1. **镜头渲染只读 `video_prompt`，不读 `sub_shots`。** 要改动作、节奏或时间轴，必须同步改 `video_prompt` 里的英文时间轴，并删掉与之矛盾的描述（如 `perfectly still`）。只改 `sub_shots`，动作不会变。例：某项目一个镜头，第一次重提开头静止约 7 秒；同步改了 `video_prompt` 后降到约 1.6 秒（实例记在该项目 `项目数据/配置/项目常量.md`）。

2. **多人同框时，提示词要逐人写出区分特征**（发型、发色、眼睛、发饰、神态），按参考图上的实际样子写，中英文都要落到；并写明「几个人长相各不相同，不是姐妹」。例：某项目一个镜头，加了逐人特征后，其中一名人物的银发才出来（实例记在该项目 `项目数据/配置/项目常量.md`）。
